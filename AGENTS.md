# PortHub: рабочие правила

Перед любым изменением:

1. Сначала воспроизвести проблему и определить конкретную причину. Не лечить её случайными версиями URL.
2. Проверить сохранённые данные старых версий (`localStorage`, URL результата, установленная PWA), а не только чистый браузер.
3. Делать минимальную правку в затронутом модуле. Не менять старые тесты и игры без прямой необходимости.
4. Общие элементы (`site-ui.js`, Service Worker, аналитика, шапка и подвал) менять только после оценки влияния на все страницы.
5. Пользовательские данные читать защитно: `null`, старый формат или повреждённый JSON не должны ломать страницу.
6. Для браузера публиковать один собранный файл модуля; исходные ES-модули остаются исходниками, но не образуют хрупкую цепочку загрузки.
7. Версия приложения, ссылки на файлы и имя PWA-кэша обновляются согласованно одним релизом.
8. Перед публикацией: профильная проверка, проверка старого состояния, `git diff --check`. После публикации дождаться GitHub Pages и проверить файлы на `porthub.fyi`.
9. Service Worker регистрирует только `site-ui.js`. Модули, тесты и игры не вызывают `navigator.serviceWorker.register()` и не подписываются на `controllerchange` самостоятельно.

## Текущий урок по совместимости

Старый режим одиночного подбора сохранял `b: null`. Экран пары не должен обращаться к `stored.name` без нормализации объекта. Любые будущие изменения формата требуют безопасной миграции или значений по умолчанию.
