# Хроники разработки: один файл — один выпуск

## Как добавить пост

1. Скопировать существующий файл из `posts/`, например `12.html`, в `13.html`.
2. В начале файла поменять `post-id` на `13`, указать дату `YYYY-MM-DD`.
3. Заполнить четыре блока `<template data-lang="ru|kk|en|fr">`.
4. В каждом блоке: один заголовок `h2`, затем текст. Обращения и шутки адаптировать, не переводить буквально.
5. Запустить из корня проекта `node scripts/build-blog.mjs` для локального просмотра.
6. Добавить исходник и новые картинки в Git. При разрешённой публикации GitHub Actions выполнит ту же сборку автоматически.

Индекс и карту сайта руками не редактировать. Номера положительные, без ведущих нулей; пропуски разрешены. Существующие номера не менять и не использовать повторно.

## Структура

```
blog/
  index.html                    # созданный сборкой общий раздел блогов
  app.js, styles.css             # совместимость со старыми страницами
  development/
    posts/1.html … 12.html       # исходники: один файл, четыре языка
    assets/                     # иллюстрации
    template.html               # общий шаблон страниц
    ui.mjs                      # четыре языка интерфейса, только для сборки
    app.js                      # лёгкая навигация, без текстов постов
    styles.css                  # оформление хроник
    index.html                  # созданный сборкой вход с выбором языка
    index.json                  # маленький манифест, количество страниц
    index/{lang}/{order}/1.json  # не больше десяти описаний на файл
    sitemap-1.xml               # созданная карта хроник
    .generated.json             # служебный список созданных файлов
ru/blog/development/             # готовые HTML, аналогично kk/en/fr
  index.html                    # первые десять выпусков
  page/2/index.html             # следующие десять
  newest/index.html            # обратный порядок
  12/index.html                # постоянный адрес одного выпуска
scripts/build-blog.mjs          # проверка исходников и генерация
scripts/stage-pages.mjs         # упаковка только публичных файлов
.github/workflows/pages.yml     # сборка и публикация в GitHub Pages
```

Шапка, переключение языков и подвал используют общую систему `site-ui.js`. Старые ссылки `/blog/#post-12` и `/ru/blog/#post-12` ведут на тот же выпуск. Без хеша `/blog/` — общий раздел, а не название хроник.

## Правила исходника

```html
<meta name="post-id" content="13">
<meta name="post-date" content="2026-09-21">
<meta name="post-status" content="published">
<template data-lang="ru">
  <h2>Заголовок</h2>
  <p class="quote">Короткий диалог.<br>Ответ персонажа.</p>
  <p>Текст выпуска.</p>
  <footer>Кодекс · подпись персонажа</footer>
</template>
<!-- Затем такие же блоки kk, en и fr со смысловыми переводами. -->
```

Использовать полную HTML-обёртку, как в существующих файлах. Фрагмент выше только показывает поля. Все четыре блока обязательны.

Допустимы `h2,h3,p,blockquote,ul,ol,li,strong,em,br,a,img,figure,figcaption,footer,code`. Скрипты, обработчики событий, стили и произвольная разметка в контенте запрещены: для них есть общие файлы оформления.

Изображения: `<img src="/blog/development/assets/limits.png" alt="Описание на языке блока" width="900" height="600">`. Сборка проверит наличие файла и добавит ленивую загрузку. Для ссылки используйте HTTPS или внутренний путь, начинающийся с `/`.

`post-status="draft"` исключает пост из индекса, HTML-страниц и карты сайта. Исходники и черновики вообще не копируются в публичный Pages-артефакт. **В публичном Git-репозитории сам исходник всё равно виден**: секреты и личные данные не хранить даже в черновиках.

Для удаления поста убрать исходник или сменить статус. Сборка удалит только ранее созданные страницы этого поста по служебному манифесту; чужие страницы не затрагивает. Старый адрес удалённого поста вернёт 404, номера других выпусков не изменятся.

## Локальная проверка

```text
node --test scripts/test-blog.mjs
node scripts/build-blog.mjs
python -m http.server 8765 --bind 127.0.0.1
```

Открыть `http://localhost:8765/ru/blog/development/`.
Опциональная браузерная проверка: `node scripts/check-blog-browser.cjs` (Playwright и Edge).

## Перед первой публикацией новой архитектуры

В GitHub Settings → Pages → Build and deployment выбрать **GitHub Actions** вместо публикации прямо из ветки. Это одноразовая настройка; локальная работа её не меняет.

Workflow на push в main или ручном запуске проверяет контент, пересобирает блог, пакует `_site/` и публикует артефакт. Генератор не использует API ИИ, D1 или Cloudflare Worker. Если файл ошибочный, публикация не начинается: действующая версия остаётся на сайте.

Локальная упаковка: `node scripts/stage-pages.mjs`. Каталог `_site/` должен отсутствовать или быть пустым: скрипт намеренно не удаляет папку автоматически. Исходники Worker, зависимости, конфигурации и черновики в артефакт не попадают.

## Масштабирование

Посетитель получает до 10 выпусков за страницу, не все тексты и не все языки. Каждая статья доступна отдельным полноценным HTML даже без JavaScript. Индекс разбит на небольшие языковые страницы. Карты блога делятся на части по 45 000 адресов; общий `sitemap.xml` ссылается на них и на сохранённую карту остальных разделов `sitemap-pages.xml`.

Папки игр, тестов и серверная часть этой миграцией не перестраиваются.

## Общие действия под постом и будущие комментарии

Нажатие заголовка или номера выпуска открывает отдельную страницу. Под постом в ленте — компактные иконки «Поделиться» и «Комментарии»; на странице выпуска — полные кнопки шаринга и копирования ссылки. Ссылки всегда ведут на конкретный языковой выпуск без временных параметров и ключей.

Настройки находятся только в `features.mjs`. Исходники `posts/*.html` для новых функций менять не нужно:

- `share` — кнопки отправки ссылки; отмена системного меню не копирует ничего автоматически.
- `comments.enabled` — включение системы комментариев. Сейчас `false`: кнопка в ленте неактивна, блоки скрыты, внешних запросов нет.
- `comments.adapter` — путь к одному локальному скрипту подключения выбранного облачного сервиса.
- `comments.preview` — `off`, `latest` или `popular`; сортировку обеспечивает адаптер и возможности выбранного сервиса.
- `comments.previewLimit` — от 1 до 5, по умолчанию 3.

Адаптер вызывает `PortHubDevelopment.registerComments({mount, mountPreview})`.
`mount({element, post})` открывает обсуждение после нажатия «Загрузить комментарии».
Необязательный `mountPreview({element, post, mode, limit})` рисует превью в ленте, только когда блок приблизится к видимой области. Если провайдер не поддерживает превью, блок скрывается.

`post` содержит `id, threadKey, lang, title, url`. Постоянный ключ `development/12` одинаков на всех языках: переводы и смена заголовка не создадут новое обсуждение. При необходимости адаптер может разделить языки через `post.lang`. Счётчики и сами комментарии будут приходить от провайдера — фиктивных чисел и отзывов нет.

Перед включением выбрать сервис, модерацию и правила конфиденциальности. Секретный API-ключ никогда не помещать в адаптер или публичный HTML. Настройки и контент пересобираются обычной командой `node scripts/build-blog.mjs`.
